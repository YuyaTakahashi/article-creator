  - SQLインジェクション（SQL Injection）とは、入力欄などに命令の一部となる文字列を送り、情報を保存するデータベースへの命令を書き換えて、不正に利用する攻撃である。
  - たとえば、ログイン画面で入力した利用者名とパスワードを、そのまま命令文につなぐ作りを考える。
  - この作りでは、利用者名に特定の記号を含めることで、パスワードを知らなくてもログインできる場合がある。
  - ## 利用者名の入力で命令が変わる
  - ログイン画面で利用者名を入力すると、アプリケーションはその文字を使ってデータベースへの命令文を組み立てる。
  - この命令文を「SQL文」と呼ぶ。
  - 組み立て方に問題があり、入力を命令の一部として扱う弱点が「SQLインジェクションの脆弱性」である。
  - ログイン画面の例では、利用者名に `wiener`、パスワードに `bluecheese` を入力すると、アプリケーションは次の命令文で照合する。
  - これは、利用者名とパスワードの両方が一致する利用者を探す処理である。
  + # SQLインジェクションとは
  + SQLインジェクションは、**入力欄に書き込んだ文字を使って、データベースへの命令を不正に変える攻撃**です。
  + データベースは、利用者の情報などを保存する仕組みです。
  + アプリケーションは「SQL文」という命令文を使って、保存された情報を探したり、書き換えたりします。
  + 入力された文字をそのままSQL文につなげる作りになっていると、攻撃者に命令を変えられることがあります。
  + その結果、パスワードなしでログインされたり、情報を盗まれたりするおそれがあります。

  + ## どのような被害があるか
  + SQLインジェクションによって、次のような被害が起こるおそれがあります。
  + - 他人のアカウントへの不正ログイン。
  + - 個人情報や非公開情報の盗み出し。
  + - 保存された情報の書き換えや削除。
  + - データベースやサービスの停止。
  + 実際に、2009年には、SQLインジェクションなどを使って企業に侵入し、1億3,000万件を超えるカード情報を盗んだとして、米国で男が起訴されています。
  + ## どうすれば防げるか
  + 基本となる対策は、**「命令」と「入力された値」を分けてデータベースに渡すこと**です。
  + この方法を「パラメータ化した問い合わせ」と呼びます。
  + 入力をそのままSQL文につなげるのではなく、先に命令の形を決め、入力された値は別に渡します。
  + すると、入力に特殊な記号が含まれていても、それは命令ではなく、ただの文字として扱われます。
  + たとえば `administrator'--` と入力されても、その文字列全体が利用者名として扱われるため、パスワードの確認を無効にできません。
  + 被害を抑えるため、次の対策も必要です。
  + - アプリケーション用のデータベースアカウントには、必要な権限だけを与える。
  + - データベースの詳しいエラーメッセージを、利用者の画面に表示しない。
  + なお、SQLインジェクションを防ぐだけでは、すべての不正アクセスは防げません。
  + 「ログインした人が、その情報を見たり変更したりしてよいか」の確認も別に必要です。
