# SQLインジェクションとは

SQLインジェクションは、**入力欄に書き込んだ文字を使って、データベースへの命令を不正に変える攻撃**です。

データベースは、利用者の情報などを保存する仕組みです。アプリケーションは「SQL文」という命令文を使って、保存された情報を探したり、書き換えたりします。

入力された文字をそのままSQL文につなげる作りになっていると、攻撃者に命令を変えられることがあります。その結果、パスワードなしでログインされたり、情報を盗まれたりするおそれがあります。

## ログイン画面での例

通常、ログインするときは、利用者名とパスワードの両方が正しいかを確認します。

たとえば、利用者名に `wiener`、パスワードに `bluecheese` を入力すると、次のSQL文で確認する作りを考えます。

```sql
SELECT * FROM users
WHERE username = 'wiener' AND password = 'bluecheese'
```

これは、次の条件に合う利用者を探す命令です。

- 利用者名が `wiener`
- パスワードが `bluecheese`

ところが、入力をそのままSQL文につなげていると、問題が起きます。

利用者名に `administrator'--` を入力し、パスワードを空欄にすると、命令は次のようになります。

```sql
SELECT * FROM users
WHERE username = 'administrator'--' AND password = ''
```

この例では、入力に含まれる記号が次のように働きます。

- `'`：利用者名の文字列を終わらせる
- `--`：それより後ろをコメントとして扱い、実行しないようにする

つまり、**パスワードを確認する部分が無視される**ため、実質的には次の命令になります。

```sql
SELECT * FROM users
WHERE username = 'administrator'
```

このような弱点があると、パスワードを知らなくても管理者としてログインできてしまう場合があります。

## どのような被害があるか

SQLインジェクションによって、次のような被害が起こるおそれがあります。

- 他人のアカウントへの不正ログイン
- 個人情報や非公開情報の盗み出し
- 保存された情報の書き換えや削除
- データベースやサービスの停止

実際に、2009年には、SQLインジェクションなどを使って企業に侵入し、1億3,000万件を超えるカード情報を盗んだとして、米国で男が起訴されています。

## どうすれば防げるか

基本となる対策は、**「命令」と「入力された値」を分けてデータベースに渡すこと**です。この方法を「パラメータ化した問い合わせ」と呼びます。

入力をそのままSQL文につなげるのではなく、先に命令の形を決め、入力された値は別に渡します。すると、入力に特殊な記号が含まれていても、それは命令ではなく、ただの文字として扱われます。

たとえば `administrator'--` と入力されても、その文字列全体が利用者名として扱われるため、パスワードの確認を無効にできません。

被害を抑えるため、次の対策も必要です。

- アプリケーション用のデータベースアカウントには、必要な権限だけを与える
- データベースの詳しいエラーメッセージを、利用者の画面に表示しない

なお、SQLインジェクションを防ぐだけでは、すべての不正アクセスは防げません。「ログインした人が、その情報を見たり変更したりしてよいか」の確認も別に必要です。

## いつから知られているか

SQLインジェクションは、少なくとも1998年には公に説明されていた攻撃手法です。ジェフ・フォリスタルは、早い時期にこの手法を説明した人物の一人です。

---

要するに、SQLインジェクションは、**「入力した文字」が「データベースへの命令」に化けてしまう問題**です。防ぐには、入力を命令文に直接つなげず、命令とデータを分けて扱います。
