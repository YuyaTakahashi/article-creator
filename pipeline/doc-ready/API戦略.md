## 最小限の説明

APIを事業の資産として外部に開き、連携や収益化に活かす経営方針

-- wp分割ライン--

API戦略（API Strategy）とは、API（アプリケーション同士をつなぐ接続の窓口）を、単なる技術的な部品ではなく、事業の資産や製品として位置づけ、外部への公開・連携・収益化まで見据えて立てる経営レベルの方針である。APIは本来、あるサービスの機能やデータを、別のソフトウェアから呼び出して使えるようにする仕組みを指す。これを「社外の開発者にも使ってもらう商品」として扱うところに、API戦略の発想がある。

たとえば決済サービスなら、支払いの仕組みを自社サイトの中だけで使うのではなく、誰でも数行のプログラムで組み込めるAPIとして公開する。すると外部の企業や個人が自社の決済機能を使ってサービスを作り始め、その利用料が新しい収益になる。自社だけでは届かなかった市場に、他者の手を借りて広がっていく。

## APIを部品でなく商品として扱う

API戦略の中心にあるのは、APIを「社内の裏方の部品」から「外に売り出す製品」へと見方を変える発想である。製品として扱うということは、機能を作って終わりにせず、使い方の説明書を整え、版を管理し、利用者を増やし、必要なら課金の仕組みまで用意する、ということだ。担当者は、スマートフォンのアプリを育てるのと同じ姿勢でAPIを運営する。

こうして手をかけたAPIは、他社が自社のサービスを組み込む入り口になる。入り口が使いやすいほど多くの相手がつながり、つながりが増えるほど自社の基盤は事業の土台として広がっていく。API戦略とは、この「つながりが増えるほど価値が育つ」流れを、あらかじめ設計して起こそうとする方針である。

## 語源・提唱者

API戦略という言葉に、ただ一人の提唱者はいない。ただし、その考え方を象徴する逸話として、Amazonの創業者Jeff¥ジェフ¥ Bezos¥ベゾス¥が2002年ごろに社内へ出したとされる「API命令（API Mandate）」がよく語られる。要点は、すべてのチームは自分たちの機能やデータをAPI経由でのみやり取りし、しかもそれを最初から社外にも公開できる形で作れ、というものだった。これに従わない者は解雇する、とまで書かれていたと伝わる。

この逸話は、元Amazonの技術者Steve¥スティーブ¥ Yegge¥イェッギ¥が2011年に書いた社内向けの文章（誤って外部へ公開された）で広まったもので、ベゾス本人やAmazonが出した一次資料は確認されていない。文言の細部は後からの回顧に基づくため、そのまま鵜呑みにはできない。それでも、社内のあらゆる機能をAPIとして作る規律が、後のAmazon Web Services（AWS）という巨大なクラウド事業につながった、という筋書きは、API戦略を語るときの原点として繰り返し引かれてきた。同じころ、SalesforceやeBay、Twitterなどが相次いでAPIを公開し、APIを軸に外部と価値をやり取りする「APIエコノミー」という言葉も広がっていった。

## 他社の力で市場を広げる

API戦略がもたらすのは、自社だけで抱え込まずに市場を広げる道である。自社の機能をAPIとして開くと、パートナーやサードパーティの開発者が、その上に新しいアプリやサービスを作り始める。自社では思いつかなかった使い道が外から生まれ、自社の基盤を土台にした製品が世の中に増えていく。開発者が増えるほど基盤の価値が高まり、その価値がさらに開発者を呼ぶという循環が回り出す。

収益の作り方も一通りではない。基本を無料で開いて裾野を広げるやり方、使った分だけ課金するやり方、月額や利用量に応じた段階制など、事業の狙いに合わせて選べる。ここで効いてくるのが、APIを使う相手である開発者の使い勝手だ。どれだけ機能が優れていても、組み込みが難しければ選ばれない。だからAPI戦略では、利用者である開発者の体験を整えることが、そのまま普及の速さを左右する。

## 数行のコードで決済を組み込めるようにする

分かりやすい例が、決済プラットフォームのStripe（ストライプ）である。Stripeが登場する前、オンライン決済を自社サービスに組み込むには数週間がかりの面倒な作業が必要だった。Stripeはこれを、わずか数行のコードを貼るだけで始められる体験に変えた。APIそのものと、その使い方を説明するドキュメントを、磨き込まれた製品として設計したのである。

Stripeが力を入れたのは、APIを使う相手である開発者の使い勝手だった。読みやすい説明書、そのまま貼り付けて動かせるサンプル、迷わせない手順を整え、「すぐに動いた」という手応えを最初に届けた。これは技術者の好みの問題ではなく、どれだけ速く採用され、どれだけ正しく組み込まれるかを左右する事業上の差になった。結果として、少数の行から始まったサービスは、世界中の企業が使う決済基盤へと育った。API戦略では、機能そのものの良さに加えて、それを使う開発者の体験（開発者体験、DX）を設計することが、そのまま事業の広がりを決める。
