# 成立条件メモ：オープンソース

```
用語の種類: 道具・手法・概念（ソフトウェアの公開と利用許諾のあり方）

成り立つ条件:
  - 条件1: ソースコード（人が読めるプログラム）が手に入り、その形でも配れる（C01, C06）
  - 条件2: ライセンスが、使う・調べる・直す・配ることを許している（C03, C07）
  - 条件3: その許しが、特定の人・集団・利用分野を外さず、再配布を受けた全員に及ぶ（C08, C09, C10）
  - 条件4: 売ることも無償で配ることも制限しない。無料であることは条件ではない（C05, C04）

隣の用語との境界:
  - ソースが見られるだけのソフト（source available）: 条件1は満たすが、条件2・3を欠くとオープンソースではない（C04）。SSPL や RSAL は「サービスとして提供する」という利用分野を制限するため、OSIに認められていない（C42, C43）
  - フリーソフトウェア: 認めるライセンスの範囲はほぼ重なるが、語の狙いが違う。free の値段と自由のあいまいさを避け、ビジネスに訴えるために生まれたのがオープンソースの呼び名（C17, C30, C33）。FSF・Stallman は両者を同一視するのは誤りとする（C34）
  - コピーレフト: オープンソースのライセンスの一種で、改変版にも同じ条件を求める（C13, C14, C16）。寛容型（Apache・BSD など）は改変版を独占製品にすることも許す（C15）
  - フォーク: 条件2（直して配ってよい）があるから成り立つ分岐。Valkey が例（C44）
  - プロプライエタリ（独占的）ソフト: 条件1・2を欠く
  - オープンソースAI: ソフトの定義を AI に広げたもので、学習データの情報・コード・重みまで求める（C46〜C48）

出典が確かめた範囲:
  ソフトウェアのライセンスとその歴史（1998年の命名・OSI設立）、OSIの定義の条文、維持体制の調査（Census II、2022年）、セキュリティ事件（XZ Utils、2024年）、ライセンス変更と分岐（Redis/Valkey、2024〜2025年）、AIへの拡張（OSAID 1.0、2024年）。デザイン資産（アイコン・書体）への広がりは今回確かめていない。

通し例の候補:
  データを一時的に置く道具（インメモリのデータストア）Redis を、自社のWebサービスに組み込んで使っている場面。
  - 条件1: Redis 7.2.4 までのソースが公開されており、そこから開発を続けられた（C44）→ 満たす
  - 条件2: BSD 3条項ライセンスで、直して配ることが許されていた（C44）→ 満たす
  - 条件3: 7.4 からの RSAL/SSPL は「サービスとして提供する」利用を制限し、条件3を外れた（C41〜C43）→ 変更前は満たし、変更後は満たさない。境界を示せる
  - 条件4: 無償か有償かではなく、許しの範囲で線が引かれた（C42）→ 満たす
  ※ 筋（誰が・何をして・どうなったか）は C41〜C45 で追える。

応用例の候補:
  Valkey の分岐（C44）。Redis のライセンス変更に対し、変更前のオープンソース版（7.2.4）から開発を続ける Valkey が Linux Foundation のもとで立ち上がり、AWS・Google Cloud などが支えた。「元のプログラムが手元にあれば、提供元の方針が変わっても続けられる」という効き目を、出典自身が「license change への対応」として結びつけている（当てはめではない）。Redis は 2025年に AGPL を選択肢に加えた（C45）。
```
