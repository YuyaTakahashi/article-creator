# チェック項目の一覧と対処

`scripts/verify_oms_adjustment.py` が出す指摘の意味と、出たときに何をするか。

判定は3段階。

- **BLOCKER** — 投入してはいけない。請求ミスに直結する。0件になるまで投入しない。
- **WARN** — 自動では白黒がつかない。人間が1件ずつ判断する。判断した内容は月次レポートに残す。
- **INFO** — 記録のみ。レポートの材料になる。

---

## 1. 請求漏れ（課金対象なのに請求していない）

| 指摘 | 判定 | 意味 | 対処 |
| --- | --- | --- | --- |
| `coverage.請求漏れ` | BLOCKER | master 上は請求期間内なのに、調整額CSVに行がない | target_data の抽出条件を確認する。BigQuery の対象月がずれていないか、荷主が抽出から漏れていないかを見る |
| `amount.CSV生成漏れ` | BLOCKER | target_data には出ているのに CSV に行がない | GAS の CSV生成が途中で切れている。再実行する |
| `master.請求開始日未登録` | BLOCKER（合意日が対象月末以前のとき）<br>WARN（それ以降） | 規約合意日は入っているが請求開始日が空。この荷主は今月請求されない | Admin で請求開始日（規約合意月の1日）を登録し、元データ更新からやり直す |
| `master.課金候補（未合意）` | INFO | マルチチャネル条件は満たすが規約合意日が空 | 請求漏れではない（未合意なら請求しないのが正しい）。件数だけ月次レポートに載せ、セールスに渡す材料にする |
| `input.CSVが空` | BLOCKER | CSV に1行もない | GAS の生成が失敗している。対象月の指定を含めて確認する |

**なぜ請求漏れが起きるか**：請求開始日の登録は営業・CSD の手作業で、合意書の受領から登録までにタイムラグがある。
`master.請求開始日未登録` は、その手作業の抜けを月初に拾うための項目。ここが実質的な最終防波堤になる。

---

## 2. 過剰請求・誤請求（請求すべきでない相手に請求している）

| 指摘 | 判定 | 意味 | 対処 |
| --- | --- | --- | --- |
| `coverage.過剰請求` | BLOCKER | 請求期間外（未開始、または請求終了日を過ぎている）なのに CSV に行がある | 解約申し出があったのに請求終了日が登録されていない可能性が高い。CSD に確認し、Admin で登録してから再生成 |
| `coverage.master不在` | BLOCKER | CSV にあるが master にいない | 荷主コードの誤りか、master の抽出条件から外れた（アカウント無効化、ショップ無効化など）。**原因を特定するまで投入しない** |
| `coverage.CSV内重複` | BLOCKER | CSV 内に同じ荷主コードが2行以上 | そのまま投入すると二重請求になる。GAS の生成ロジックを確認する |
| `master.課金条件を満たさない請求対象` | WARN | 請求期間内だが、有効ショップの組み合わせが課金条件を満たさない | ショップを停止して実質シングルチャネルになった可能性。解約手続きが漏れていないかCSDに確認。**最低3ヶ月ルールにより、条件を外れても請求継続が正しい場合がある** |
| `master.無効アカウントが請求対象` | WARN | アカウント有効フラグが 0 なのに請求期間内 | OPL 自体の利用停止と請求終了の整合を確認する |
| `master.課金条件が判別不能` | WARN | BASE の新アーキ／旧アーキが master からは判別できず、それによって課金対象かどうかが変わる | Admin で該当荷主を開き、`(Fraise)` 表記があれば新アーキ＝課金対象、なければ旧アーキ＝対象外。判断結果をレポートに書く |
| `master.請求期間が逆転` | BLOCKER | 請求終了日が請求開始日より前 | master の入力ミス。修正してから再生成 |

### 課金対象の判定ロジック（このツールが実装しているもの）

有効なショップだけを見て、次のチャネルを「課金カウント対象」として数える。2つ以上なら課金対象。

- カウントする: `shopify` `ecforce` `rakuten` `yahoo` `makeshop` `stores` `generic_b2c` `tiktok` `qoo10`
- カウントしない: `nextengine` `amazon`（FBA・受注連携なし）
- 判別不能: `thebase`（新アーキならカウント、旧アーキならカウントしない）

同一チャネルの複数ショップも、それぞれ1つとして数える（Shopify × Shopify は課金対象）。

**未解決の論点**：PJドキュメントの組み合わせ判定表では、BASE旧アーキ・NE旧アーキ・Amazon FBA の各行で
TikTokShop と Qoo10 の列だけが「◯」になっている。表の他の部分（旧アーキは他のどのチャネルと組んでも「X」）
と矛盾しており、列を一律に埋めた記入ミスの可能性が高い。このツールは矛盾のない側（旧アーキはカウントしない）
を実装している。**該当する組み合わせの荷主が現れたら、実装を信じずPJ側に確認すること。**

## 3. 金額誤り

| 指摘 | 判定 | 意味 | 対処 |
| --- | --- | --- | --- |
| `amount.再計算不一致` | BLOCKER | 出荷件数から独立に再計算した金額と CSV の amount が違う | **絶対に投入しない。** GAS の計算式か単価表が変わった疑い。単価表シートとこのツールの `TIERS` 定数を突き合わせる |
| `target.段配分の誤り` | BLOCKER | target_data の段別件数が階段式の配分と一致しない | BigQuery 側の集計ロジックを確認 |
| `target.段別件数の合計不一致` | BLOCKER | 段別件数の合計が shipment_cnt と合わない | 同上 |
| `amount.基本料未満` | BLOCKER | 金額が基本利用料 10,000円 を下回っている | 基本料が乗っていない。生成ロジックを確認 |
| `amount.元データ不在` | BLOCKER | CSV に行があるが target_data に対応行がない | 金額の根拠を確認できない状態。投入しない |
| `target.基本料が既定と異なる` | WARN | fixed_fee が 10,000円 でない | 料金改定があったなら、このツールの `FIXED_FEE` も直す |
| `memo.合計不一致` `memo.件数不一致` `memo.段別件数不一致` `memo.内訳合計不一致` `memo.内訳の掛け算が誤り` `memo.単価が料金表と異なる` | BLOCKER | 調整理由の本文と実際の金額・件数が食い違っている | **memo は請求書に載り荷主の目に触れる。**金額が正しくても本文が違えば問い合わせになる。テンプレートを直す |
| `memo.空` | BLOCKER | 調整理由が空 | 請求書に理由が出ない。必ず入れる |
| `memo.表題不一致` `memo.件数を読み取れない` `memo.合計を読み取れない` `memo.内訳の段数が合わない` | WARN | memo テンプレートが変わった可能性 | テンプレート変更が意図的なら、このツールの `MEMO_TITLE` と正規表現を合わせる |
| `target.件数不正` `csv.amount不正` | BLOCKER | 数値として読めない値が入っている | 生成の失敗。再生成する |

### 料金表（このツールが実装しているもの）

- 基本利用料：10,000円／月（固定）
- 従量課金：出荷件数の**階段式**。全体件数に一律の単価をかけるのではなく、各段に含まれる件数分だけその段の単価がかかる

| 段 | 単価 |
| --- | ---: |
| 1〜500件 | 0円 |
| 501〜5,000件 | 19円 |
| 5,001〜10,000件 | 9円 |
| 10,001〜15,000件 | 5円 |
| 15,001〜20,000件 | 3円 |
| 20,001件〜 | 1円 |

例：8,000件 → 10,000 + (500×0) + (4,500×19) + (3,000×9) = 122,500円

料金改定があったら `scripts/verify_oms_adjustment.py` の `TIERS` と `FIXED_FEE` を直す。
直し忘れると全件が `amount.再計算不一致` になるので、改定を見落とすことはない。

## 4. CSVの形式

| 指摘 | 判定 | 意味 |
| --- | --- | --- |
| `format.列不足` | BLOCKER | Admin のテンプレートの必須列が足りない |
| `format.固定値の誤り` | BLOCKER | `detailDiv=0`（その他）、`taxInputDiv=0`（税抜き）、`wholesaleDiv=0`（分配なし）、`wholesaleValue=0` のいずれかが違う。**税区分の誤りは金額の誤りと同じ重さ** |
| `format.必須項目が空` | BLOCKER | acc または amount が空 |
| `csv.調整日付が対象月末でない` | BLOCKER | targetDate が対象月の末日でない。請求月がずれる |
| `target.対象日が対象月末でない` `target.対象月不一致` | BLOCKER | BigQuery の抽出月がずれている。**先月分を回したつもりで先々月を回している事故**がここで止まる |
| `csv.倉庫コード不一致` `csv.倉庫コード空` | BLOCKER | 倉庫コードが target_data と違う、または空 |
| `format.余分な列` `format.列順が異なる` | WARN | テンプレートが変わった可能性。Admin の取り込み仕様を確認 |
| `format.免税額が入っている` | WARN | taxExemptAmount は明細区分が関税のときだけ有効 |

## 5. 前月比（異常検知）

| 指摘 | 判定 | 意味 | 対処 |
| --- | --- | --- | --- |
| `mom.前月あり今月なし` | BLOCKER | 前月請求していた荷主が今月消えたが、請求終了日が登録されていない | 請求漏れか、抽出条件の事故。原因を特定する |
| `mom.金額の急増` | WARN | 前月の2倍以上かつ 50,000円以上の増加 | 出荷件数が実際に伸びたのか、抽出条件の誤りかを target_data の件数で確認する |
| `mom.金額の急減` | WARN | 50,000円以上の減少 | 同上 |
| `mom.新規請求` `mom.請求終了` | INFO | 当月の出入り。月次レポートとSlack報告に載せる | — |

閾値は `MOM_AMOUNT_RATIO`（2.0倍）と `MOM_AMOUNT_ABS`（50,000円）。運用しながら調整する。

## 6. 投入後の突合

| 指摘 | 判定 | 意味 | 対処 |
| --- | --- | --- | --- |
| `post.登録されていない` | BLOCKER | CSV にあるのに Admin に登録されていない | 取り込みが途中で失敗している。Admin の取り込み結果を確認し、不足分だけ再投入するか全件やり直すかを判断する |
| `post.二重登録` | BLOCKER | 同じ荷主・同じ対象日の調整額が複数登録されている | 同じ CSV を2回投入した。**重複分を削除するまで報告しない** |
| `post.金額不一致` | BLOCKER | 登録額が CSV と違う | 手修正が入ったか、別の CSV を投入した |
| `post.CSVにない登録` | BLOCKER | CSV に無い調整額が同じ対象日に登録されている | 手入力が混ざっている。意図的なものか確認する |

投入後チェックが全て通ったときだけ、「登録済み件数＝CSV行数」「登録済み総額＝請求総額」が
レポート上で一致する。この2つの一致を確認せずに Slack 報告へ進まない。

## 7. データ衛生（請求そのものは止めないが、放置すると事故になる）

| 指摘 | 判定 | 意味 |
| --- | --- | --- |
| `master.請求開始日が月初でない` | WARN | 日割りを行わない運用なので、請求開始日は月初1日に揃える。中途半端な日付が入っていると月境界の判定で事故が起きやすい |
| `master.請求終了日が月末でない` | WARN | 同上。終了日は終了月の末日に揃える |
| `master.最低利用期間3ヶ月未満` | WARN | 規約上は最低3ヶ月。請求終了日が早すぎる。CSD に確認する |
| `target.重複行` | BLOCKER | target_data に同じ荷主が複数行ある |

## チェックが「通った」ことの意味

BLOCKER が0件でも、次は保証していない。人間の最終確認が必要な理由がここにある。

- **出荷件数そのものの正しさ**。BigQuery が返した件数を正として扱っており、
  モール出荷を除外できているか、キャンセル分を含んでいないかまでは見ていない。
- **規約合意の実在**。master の合意日が入っていることは見るが、合意書が実際にあるかは見ていない。
- **BASE の新旧アーキ**。判別できないものは WARN で人間に回している。
- **キャンペーン適用**。6ヶ月無料キャンペーンの対象荷主かどうかは、このツールは判定していない。
  キャンペーン対象が請求されていないか、目視で確認する必要がある。
